# РКИИЭ 2.0 — демонстрационный стенд

**Демо: https://1lux0r1.github.io/AISRKII/**

Публикуется автоматически из ветки `main` (`.github/workflows/pages.yml`).
Картографическая подложка загружается браузером посетителя, поэтому дома и
дороги отображаются полностью.

Рабочее демо интерфейса мониторинга объектов ресурсоснабжения города, собранное
по обновлённому дизайну. Система показывает сведения, собранные от
ресурсоснабжающих организаций (РСО), на карте города — не в реальном времени, а
по последней принятой выгрузке.

## Запуск

Готовое демо открывается по адресу выше. Локально:

```bash
npm start          # http://127.0.0.1:4173
```

Сборка не требуется: чистый JavaScript (ES-модули), Leaflet подключён локально из
`vendor/`. Открывать `index.html` напрямую из файловой системы нельзя — модули
требуют http-origin, поэтому в комплекте статический сервер без зависимостей
(`tools/serve.js`, только стандартная библиотека Node ≥ 18).

Порт задаётся аргументом или переменной окружения: `npm start -- 8080`, `PORT=8080 npm start`.

### Сборка в один файл

```bash
npm install        # нужен только для сборки
npm run bundle     # dist/rkiie-demo.html
```

Стили, Leaflet и код приложения встраиваются внутрь страницы — получается один
самодостаточный HTML-файл, который можно передать или опубликовать там, где нет
доступа к соседним файлам. Для повседневной работы сборка не нужна.

## Что уже работает

**Карта.** Уровни детализации переключаются по масштабу автоматически:

| Масштаб | Что на карте |
|---|---|
| город | контуры 12 административных округов, плашки с числом открытых событий |
| округ | контуры районов поверх округов |
| район | кластеры с числом объектов, цвет — преобладающий ресурс |
| объект | отдельные объекты и участки сетей, цвет — ресурс |

Клик по территории открывает карточку со сводкой; в ней две вкладки —
**«Объекты»** (состав реестра, протяжённость сетей, районы) и
**«Потребление»** (объёмы в отраслевых единицах, нагрузка, отклонение к
прошлому периоду, структура по категориям потребителей и учёт критической
инфраструктуры). Такая же карточка открывается после выделения произвольной
области. Клик по объекту открывает
паспорт в правой панели.

**Фильтры.** Территория (округ → район → улица, произвольная область), ресурс
с типами объектов, организация (список зависит от выбранного ресурса),
состояние. Активные фильтры выносятся чипами под шапкой; они же снимаются
оттуда.

**Типы объектов выбираются внутри ресурса.** Отдельного блока «Тип объекта»
нет: состав типов зависит от ресурса — тепловые пункты бывают только в
теплоснабжении, подстанции только в электроснабжении, а сети и оборудование
есть у всех. При включении ресурса отмечаются все его типы; снятие последнего
выключает ресурс целиком. Частичный выбор помечается чёрточкой вместо
галочки — галочка означала бы «выбраны все».

**Шаблоны поиска.** Набор фильтров по ресурсам, типам, состоянию и организациям
сохраняется под именем и применяется одним выбором. Шесть встроенных шаблонов
закрывают частые задачи («Технологические нарушения», «Сети без данных»,
«Теплоснабжение: источники и ЦТП» и другие), пользовательские хранятся в
браузере. Шаблон задаёт, *что* искать, и не меняет территориальный охват.

**Объекты показываются после выбора ресурса.** Пока ресурс не отмечен, на карте
остаются только границы территорий: шесть систем ресурсоснабжения вперемешку
нечитаемы. Вместо пустой карты выводится подсказка.

**Панель сведений.** Контекстная: город, округ, район, произвольная область или
объект — у каждого свой набор вкладок и показателей.

**Инструменты карты.** Измерение расстояния, метка, выделение произвольной
области (по ней сразу считается сводка), смена подложки, легенда, полноэкранный
режим, список объектов. Инструменты доступны при выключенном «Режиме
просмотра».

**Список объектов** открывается в модальном окне — из панели инструментов,
из карточки района и из карточки выделенной области. Внутри окна: поиск по
адресу и наименованию, выпадающие фильтры по ресурсу, типу и состоянию,
постраничная навигация. Эти фильтры сужают уже отобранный набор и не меняют
состояние карты: это разбор конкретной выборки, а не новая настройка фильтра.
Строка выбирается мышью или с клавиатуры, выбор открывает паспорт объекта.

**Разделы.** «Проверка данных» — журнал событий и расхождений в выгрузках;
«Аналитика» — распределение по округам, ресурсам и организациям с учётом
действующих фильтров; «Отчёты» — параметры выгрузки и шаблоны;
«Администрирование» — состав настроек.

**Глобальный поиск** по округам, районам, организациям, крупным источникам и
номерам событий — с переходом к найденному.

## Устройство

```
index.html            разметка-каркас, подключение стилей и точки входа
src/
  main.js             сборка приложения, обработка действий
  state.js            хранилище состояния (подписка + патч по темам)
  data/
    catalog.js        справочники: ресурсы, типы, РСО, округа, районы
    geo.js            загрузка геометрии территорий и операции над полигонами
    territories.js    СГЕНЕРИРОВАННЫЙ файл с контурами (tools/build-geo.js)
    registry.js       таблица агрегации и свод показателей
    features.js       объекты карты (точки и участки сетей)
    incidents.js      события мониторинга
    consumption.js    потребление ресурсов по территориям
    presets.js        шаблоны поиска: встроенные и пользовательские
                      (фильтр хранит типы отдельно для каждого ресурса)
    model.js          единая точка доступа к данным + поиск
  ui/                 header, chips, filters, map, inspector, objectmodal,
                      sections, footer, select, icons, toast
  utils/              dom, format (ru-локаль), rng (детерминированный)
styles/               tokens.css, app.css, map.css
vendor/leaflet/       Leaflet 1.9.4 (BSD-2-Clause), подключён локально
tools/serve.js        статический сервер для разработки
tools/bundle.js       сборка демо в один HTML-файл (esbuild)
tools/build-geo.js    подготовка контуров территорий из открытых данных
data/                 исходный GeoJSON границ районов
```

## О данных

Демо работает на сгенерированных данных — боевого подключения к источникам нет.
Генерация детерминированная (`utils/rng.js`), поэтому при каждой загрузке
показатели одинаковы.

**Критическая инфраструктура** — объекты, перерыв в снабжении которых
недопустим: экстренные службы, связь и ЦОД, медицина, водоснабжение,
источники теплоснабжения, транспорт, образование. По каждой категории
показаны число объектов, категория надёжности электроснабжения
(«I особая» — три независимых источника, «I» — два, «II» — резерв по решению
эксплуатирующей организации) и доля в потреблении территории. Отдельно —
резервирование: сколько объектов имеет второй независимый ввод и автономный
источник, запас автономной работы и сколько требуют внимания.

**Потребление** выводится из числа потребителей в реестре, поэтому согласовано
с составом объектов, и считается в отраслевых единицах: тепло в гигакалориях,
электроэнергия в киловатт-часах, вода и газ в кубометрах. Заметным цветом
выделяется отклонение больше 10 % в любую сторону — рост потребления сам по
себе не авария, разбирательства требует именно отклонение.

**Показатели.** Хранится не список из сотен тысяч записей, а разреженная таблица
ячеек агрегации «район × тип × ресурс × организация» (около 7 тысяч ячеек).
Городские итоги откалиброваны по контрольным значениям из макета
(`CITY_TARGETS` в `data/catalog.js`): 71 источник, 5 432 тепловых пункта,
132 814 потребителей, 2 356 км сетей. Разложение по районам выполняется методом
наибольших остатков, поэтому суммы по районам и округам сходятся с городскими
точно, без расхождений между уровнями.

**Объекты на карте.** Строятся по требованию для видимых районов и кэшируются.
Для массовых типов (потребители, оборудование, участки сетей) отображается
выборка — счётчики при этом берутся из реестра, а не из числа нарисованных
точек; доля выборки указана в легенде и в шапке списка объектов.

**Геометрия — настоящая.** Контуры 125 районов «старой» Москвы и Зеленограда
взяты из открытых данных OpenStreetMap (набор `click_that_hood`, ODbL,
© участники OpenStreetMap). Соответствие «район → округ» берётся из справочника
по наименованию, контуры округов получаются объединением их районов, геометрия
упрощается с допуском около 11 метров. Всё это делает `tools/build-geo.js`,
результат лежит в сгенерированном `src/data/territories.js` — редактировать его
руками не нужно:

```bash
npm run build:geo
```

Анклавы сохранены: у Восточного, Внукова и Кунцева контур состоит из нескольких
колец, и объекты распределяются по ним пропорционально площади.

Границ поселений Новомосковского и Троицкого округов в наборе нет. Эти два
округа остаются в справочнике и в сводках (округов по-прежнему 12, районов и
поселений 146), но на карту не выводятся — рисовать выдуманный контур рядом с
реальными границами нельзя. В списке округов они помечены «без контура».

**Дома и дороги — на подложке.** Застройка, улицы и адресные подписи приходят
с тайлового сервиса, а не из данных приложения. Кнопка «Подложка карты» в
панели инструментов переключает четыре варианта:

| Подложка | Источник | Что показывает |
|---|---|---|
| Схема | OpenStreetMap | дома, дороги и адреса (по умолчанию) |
| Контрастная | Esri World Light Gray | приглушённый фон, когда важны только объекты |
| Космоснимок | Esri World Imagery | реальную застройку |
| Без подложки | — | только контуры территорий и объекты |

Все источники работают без ключа доступа. CARTO не используется: сервис
перешёл на платную модель и печатает поверх своих тайлов водяной знак
«API KEY REQUIRED».

Масштаб доходит до z19 — это уровень отдельных зданий. На космоснимке
заливка контуров приглушается, а подписи районов становятся светлыми, иначе
они теряются на снимке.

Тайловый сервер OpenStreetMap рассчитан на небольшую нагрузку: для рабочего
контура адрес подложки меняется на внутренний в `BASE_LAYERS`
(`src/ui/map.js`).

Встроить дома и дороги в само приложение нельзя: в Москве больше миллиона
контуров зданий и десятки тысяч улиц — это сотни мегабайт, которые браузер не
потянет. Именно для этого и существует тайловый сервис; в рабочем контуре его
адрес просто меняется на внутренний в `BASE_LAYERS` (`src/ui/map.js`).

Если доступа к тайлам нет — в закрытом контуре или в песочнице с
ограничительной CSP — приложение сообщит об этом и продолжит работать на
контурах территорий: под ними проступает координатная сетка, чтобы поле
читалось как карта.

## Что стоит доработать

- подключение к реальным источникам вместо генератора: `data/model.js` — единственный
  модуль, который знает, откуда берутся данные;
- границы поселений Новомосковского и Троицкого округов;
- серверная агрегация и постраничная выдача объектов вместо клиентской;
- фильтр «Улица / квартал» пока не сужает выборку — нужен адресный классификатор;
- привязка объектов к домам: сейчас потребители расставлены случайно внутри
  района, а не по реальным адресам — нужен адресный реестр с координатами;
- сохранение областей, отчётов и избранного на сервере.
